# Evacuation Route Simulator

A command-line tool that plans safe evacuation routes through a small city map, reroutes people around live hazards (like fires or floods), and simulates moving groups of people from buildings to the nearest safe zone that still has room for them.

I built this for my **CSE1021 (Introduction to Problem Solving / Python)** "Build Your Own Project" submission at VIT Bhopal.

## Why this project

Every disaster-management video I'd watched kept repeating the same line: the biggest killer in an emergency isn't the hazard itself, it's people not knowing which way is actually safe to go. That stuck with me, so instead of doing another to-do list or calculator style project, I wanted something with a bit of real logic behind it — pathfinding, not just data entry.

The idea: model a small city as a graph of buildings, road junctions, and safe zones. When a hazard shows up somewhere on the map, the roads near it get more "expensive" to travel (or blocked completely if you're right next to it), and the route planner automatically finds a way around it instead of just walking straight through.

## What it actually does

The whole thing runs as a menu-driven CLI (`main_program.py`). Once you run it, you can:

1. **View the map** — see every location (buildings, junctions, safe zones) and any hazards currently active.
2. **Add a hazard** — pick a location, give it a radius and a severity (0 to 1). Anything close to the center gets fully blocked; anything further out just gets riskier/slower.
3. **Remove a hazard** — clears it and recalculates the road costs from scratch.
4. **Find a route** — Dijkstra's algorithm finds the cheapest path between two points, or the nearest safe zone with free space if you don't specify a destination. It also saves a map image of that route.
5. **Run an evacuation simulation** — give it a list of buildings and how many people are in each, and it'll route every group to the nearest safe zone that still has capacity, updating that zone's load as it goes (bigger groups get processed first).
6. **Save a picture of the map** — a matplotlib plot showing every road, hazard zone, and location, color-coded by hazard level.
7. **Export the last simulation to CSV** — who went where, how many people, and the route they took.

## How the "safety cost" works

Every road (edge) has a base distance. On top of that:

- If a hazard's *severity radius* touches the midpoint of a road, that road's hazard level goes up (closer to the center = higher).
- If a hazard's *critical radius* (30% of the full radius) touches it, the road is marked as fully blocked and Dijkstra will never use it.
- The actual cost used for pathfinding is `distance * (1 + 5 * hazard_level)`, so a road right at the edge of a hazard is a little slower, and a road deep inside one is heavily penalized — but only a *fully blocked* road is completely excluded.

This is why the "before hazard" and "after hazard" screenshots below show two different routes for the same start/end pair.

## Getting it running

```bash
# 1. clone the repo
git clone https://github.com/<your-username>/evacuation-route-simulator.git
cd evacuation-route-simulator

# 2. (optional but recommended) set up a virtual environment
python -m venv venv
venv\Scripts\activate      # Windows
source venv/bin/activate   # macOS/Linux

# 3. install dependencies
pip install -r requirements.txt

# 4. run it
python main_program.py
```

You'll get a menu — just type the number of what you want to do and follow the prompts. Example flow:

```
Pick an option: 4
Start node: B1
Destination node (leave blank for nearest safe zone):
Route found (3 stops, cost 13.0):
  B1 -> I1 -> S1
map saved to output/route.png
```

To regenerate all the sample screenshots used in this README/report in one go:

```bash
python sample_outputs.py
```

## Testing

There's a basic sanity test in `tests/test_basic.py` that builds a tiny 3-node graph and checks that:
- Dijkstra picks the shortest path when nothing's blocked.
- It correctly reroutes when the shortest edge is blocked.

Run it with:

```bash
python tests/test_basic.py
```

It should print `all tests passed`. It's a plain assertion-based script rather than a `pytest`/`unittest` suite — enough to catch regressions in the core pathfinding logic without over-engineering a project this size.

## Known limitations / things I'd improve with more time

- The map is hardcoded to one small JSON file — there's no UI to draw a new city layout, you have to hand-edit `data/map.json`.
- No persistence between runs — hazards and safe-zone loads reset every time you restart `main_program.py`.
- Only Dijkstra is implemented. An A* version (using straight-line distance as a heuristic, since nodes already have x/y coordinates) would speed things up on a bigger map.
- Input validation on the CLI is minimal — typing a wrong node ID is handled, but there's no protection against, say, negative population counts.

## Future enhancements

- Load bigger, real city maps (OpenStreetMap export → convert to this JSON format).
- A* search using the existing x/y coordinates as the heuristic.
- A simple web front-end instead of a CLI, so multiple people could view the same evacuation state at once.
- Save simulation/hazard history to a small local database instead of losing state on exit.
